## 003. 自分の財布で払った記録は、記録に印を付けて未精算として追う

- 日付: 2026-11-22
- 対象: ENTRY の `settled`・`paidBy`、firestore.rules の validEntry、記録画面・未精算の画面・記録を直す画面

### 決定

共通の財布でなく自分の財布で払った共通の出費は、普通の記録に `settled: false` と `paidBy` を付けて残す。共通の財布から返したら `settled: true` にする。本人に3点を聞いて決めた。

- 今月の合計・予算には、立て替えた時点で入れる。あとで共通の財布から出ていくお金なので、残りが実態に合う。
- 払った人は記録した人（その端末の呼び名）。操作が1つで済む。あとから記録を直して未精算にするときも、払った人はその記録を書いた人にする（相手の付け忘れをこちらで直しても、返す相手が入れ替わらないように）。
- 精算は1件ずつでも、人ごとにまとめてでもできる。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| 精算したときに合計へ入れる | 精算するまで残りが多く見える。本人が「入れる」を選んだ |
| 合計・予算と別枠にする | 同上 |
| 立て替えのたびに払った人を選ぶ | 操作が1つ増える。本人が「記録した人」を選んだ |
| 未精算を別のコレクションに持つ | 同じ出費を二重に持つことになり、合計に入れる・カテゴリ別に出すのに突き合わせが要る |
| 記録画面に行を1つ足して財布を選ばせる | 小さい画面で「記録する」まで1画面に収まらなくなる。メモ欄の横の切り替えにした |

### 影響範囲

- rules の validEntry に `paidBy`・`settled` を任意の項目として足した。アプリより先に rules を出す。
- 記録を直す保存は updateDoc なので、古い版を開いたままの端末が直しても印は消えない。
- 呼び名を途中で変えると、前の呼び名の未精算は別の人として並ぶ（記録を直す画面では名前のまま出る）。

### 検証

- `tests/model.test.ts`（財布の読み分け・人ごとのまとめ）、`tests/app.test.tsx`（未精算で記録・印と入口・精算と元に戻す・払った財布を変える）。
- 保存先とつないだ確認は、本物の家計簿に試し書きしない決まりのため行っていない。
