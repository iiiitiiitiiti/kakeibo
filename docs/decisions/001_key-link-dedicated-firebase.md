## 001. 鍵つきリンクと家計簿専用の Firebase で2人が共有する

- 日付: 2026-11-22
- 対象: 保存先（Firebase プロジェクト kakeibo-c2f4e1）・firestore.rules・共有のリンク

### 決定

かいものと同じく、ログインなしで鍵入りのリンク（`#k=<鍵>`）を開けば使える形にする。保存先は家計簿専用の Firebase を新しく作り、東京に置く。本人がリンクが漏れたときの危険（見られる・書き換えられる）を聞いたうえで選んだ。

### 背景

かいもので実績のある型だが、かいものの根拠（docs/decisions/001 of kaimono）は「守るのが買い物の品目だから足りる」だった。家計の支出では前提が変わるので、プランレビュー（fable-advisor）の指摘で本人に確かめ直した。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| かいものの Firebase に相乗り | rules が1ファイルに同居し、片方を直すともう片方を壊しうる。本人も専用を選んだ |
| Google ログイン | 相手の Google アカウントと設定の手間が増える。本人がリンク方式を選んだ |
| Artifact の db | 相手にも Claude のアカウントと招待が要る |
| 予算を1文書の map に持つ | rules が map の中身を検査できない。`budgets/{YYYY-MM}` の1月1文書にした |
| 最初のカテゴリを保存先に書き込む | 2台目の初回起動で1台目の変更を元に戻す。コードに持ち、変えた分だけ保存先に置く |

### 影響範囲

- リンクが漏れたら鍵を作り直す（手順は docs/DESIGN.md の「鍵を作り直すとき」）。
- 将来「相手に見せない個人の帳簿」を足すなら、自分だけの鍵で別の帳簿を持つ形になる。

### 検証

2026-11-22 に REST で確かめた: 違う鍵は 403、正しい鍵は読み書きできる、金額0・日付の形違い・知らない項目・カテゴリの削除・月の形違いの予算・帳簿の一覧はどれも 403。2つのクライアントで片方の記録がもう片方に 154ms で届いた。
