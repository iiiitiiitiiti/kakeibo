## 006. 送った公開の知らせは、GitHub Actions の手動の流れで書き換える

- 日付: 2026-11-25
- 対象: かけいぼの `.github/notify-discord.sh`・`.github/workflows/deploy.yml` の `notify`・新しく足した `.github/workflows/edit-discord.yml`

### 決定

Discord へ送った公開の知らせを、あとから書き換えられるようにする。書き換えは `edit-discord.yml` を手で動かして行う（`workflow_dispatch`）。渡すのは、書き換える投稿（`last` か Discord の投稿リンク）と、書き換えた後の変わった点の全行。送るときは `?wait=true` で投稿の番号を受け取り、成果物 `discord-message` に残す。`last` はその一番新しいものを読む。書き換えには Discord のウェブフックの「投稿の編集」（`PATCH /webhooks/{id}/{token}/messages/{message_id}`）を使う。

あわせて、知らせの文（`お知らせ:` の行と書き換えの文）は送る前に akapen スキルへ通す。

### 背景

2026-11-25 にユーザーが、送った知らせを書き換える機能を求めた（メイン経由）。ユーザーが投稿リンクを貼るか「最後の投稿を直して」と言えば書き換えられる形にする。ふたりのレシピ帳では同じ日に、PC の中のスクリプト（`~/.claude/scripts/discord-notify.py --edit`）で同じ機能を入れている。同じ依頼で、知らせの文を送る前に akapen へ通すことも決まった。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| レシピ帳と同じく PC のスクリプトで書き換える | 送り先の URL は GitHub のシークレットにしか無く、読み出せない。PC にも置くと、URL の置き場が2つになり、Mac と Windows の両方で置く手間が増える |
| 投稿の番号をリポにコミットして残す | 公開のたびに Actions からコミットが増え、Mac と Windows の pull が毎回ずれる。書き込みの権限も要る |
| 投稿の番号を GitHub のリポの変数に残す | Actions の標準の権限では変数を書けず、別の鍵が要る |
| 番号を残さず、いつも投稿リンクで渡す | 「最後の投稿を直して」と言うだけで済む形にできない |

### 影響範囲

- `notify-discord.sh` に書き換えの動き（`EDIT_MESSAGE`・`NOTES_TEXT`）と番号を残す動き（`MESSAGE_ID_FILE`）を足した。どちらも渡さなければ前と同じに動く。
- `notify-discord.sh` は、かいもの・動物園・水族館ログと同じ中身にする決まり（005）。この時点では、ほかの2つは前の版のまま。書き換えが要るときは、この版と `edit-discord.yml` を写し、`APP_NAME` をそのツールの名前にする。
- 成果物は90日で消える。それより前の投稿と、この機能より前の投稿は、投稿リンクで書き換える。
- 書き換えられるのは、このウェブフックで送った投稿だけ。ほかのウェブフックや人の投稿は Discord が断る。
- 書き換えの前も、送る前と同じく `dry_run` で中身を出し、ユーザーの承認を得る。書き換えるときは先に投稿の今の文を読んで出す（dry_run でも）。
  - 番号が残らないことがある（送った直後に次の公開で取り消された・成果物を残す手順が失敗した）。そのとき `last` は1つ前の投稿を指す。今の文を見れば取り違えに気づける（Fable の最終確認の指摘）。
- 番号を残す手順は `continue-on-error` にする。失敗で公開全体を失敗にすると、次の公開の起点が古いままになり、同じお知らせをもう一度送るため。
- 送り先の URL の後ろの `?thread_id=` などと末尾の `/` は、分けてから付け直す。どちらが付いていても送れるようにするため。

### 検証

- 2026-11-25 に手元の bash から、Discord の代わりの小さな受け口へ送って次を確かめた。
  - 送るときに `?wait=true` を付け、返った番号をファイルに残す
  - リンク（末尾の `?` 以降つき）から番号を取り出して `PATCH` する
  - 別の投稿の番号なら「見つかりません」で止まる
  - 番号の無いリンク・空の文・last の記録なし・URL なしのときは止まる
  - 書き換えの文の先頭の「- 」と空白と CRLF と同じ文を整える
  - 書き換える前に今の文を読んで出し、見つからなければ書き換えずに止まる
  - URL の末尾の `/` と `?thread_id=` を付け直す（送る・読む・書き換えるの3つとも）
- 本物のリポで、成果物を探す `gh api` の絞り込みと `gh run download` が動くことを確かめた。
