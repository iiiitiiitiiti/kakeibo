## 004. 公開の知らせは、公開の手順の最後に Discord のウェブフックへ送る

- 日付: 2026-11-22
- 対象: `.github/workflows/deploy.yml` の `notify`、GitHub のシークレット `DISCORD_WEBHOOK_URL`

### 決定

「アップデートが入ったら Discord 等に知らせたい」という依頼を、アプリの新しい版を公開したときの知らせと読んだ。公開（Pages への反映）が成功したあとに動くジョブを足し、その push に含まれるコミットのうち `feat:`・`fix:` の1行目を箇条書きにして、Discord のウェブフックへ送る。

- 公開に失敗したときは送らない（`needs: deploy`）。
- シークレットが無ければ何もせず成功で終わる。知らせを使わない間も公開は止まらない。
- コミットの文面は環境変数で渡し、シェルの文へ直接は埋め込まない。メンションは `allowed_mentions` で無効にする。1900字で切る。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| Discord のウェブフックの GitHub 用の受け口（URL の末尾に `/github`）を GitHub の Webhooks に登録する | 設定だけで済むが、すべての push が英語のコミット一覧として流れる。公開の成否と関係なく出る。相手が読む文にならない |
| 既にある Discord の bot（別の VM で動いている）から送る | 家計簿アプリは bot とつながない決まり。bot の側に公開を知る仕組みを足すことになる |
| アプリの中に「新しくなりました」を出す | 開かないと気づけない。依頼は Discord などへの知らせ |
| 変わった点を別のファイル（更新履歴）に書いて、それを送る | 公開のたびに書く手間が増える。コミットの1行目を使う人の言葉で書けば足りる |

### 影響範囲

- `feat:`・`fix:` の1行目がそのまま2人に届く。作り手の言葉（部品の名前など）を書かない。
- 記録や予算の中身は送らない（コミットの文面だけ）。
- 送り先の URL を知っている人はそのチャンネルへ書き込める。鍵と同じ扱いにして、リポ・記録・チャットに書かない。

### 検証

- ジョブの中身を手元の bash で動かし、`feat:`・`fix:` だけを拾うこと、`docs:` だけなら送らないこと、シークレットが空なら送らないこと、長い文が1900字で切れることを確かめた（送信は差し替え）。
- 本物の Discord への送信は、シークレットを入れたあとの最初の公開で確かめる（2026-11-22 時点では未確認）。
